# 통신 열화 스윕 — harness_sitl (zero-shot, 재학습 없음)

## 1. 조건

- 정책: `pontoon_rl/out/n1/ppo_sc3_final.zip` → ONNX. **재학습하지 않았다.**
- 에피소드 10개 (시드 1000~1009), 도메인 랜덤화 ON, 링크 시드 7.
- 1 틱 = 물리 20 ms. 제어주기 = 5 틱 = 100 ms. 에피소드 60 s.
- 지연은 `/pontoon/state`(상행) 과 `/tug_command`(하행) 에 건다.
- 손실은 두 토픽에 동시에 건다. 손실 시 수신측은 **직전 값을 유지**
  한다(sample-and-hold = 실물 Pixhawk 거동, 수신 타임아웃 없음).

## 2. ★ 지표를 종단오차만 쓰면 안 된다

- 60 s 정지정렬 과제라 제어기가 끝에서 정착해, **상태지연 1~5 틱에서
  종단오차가 공칭과 소수 4자리까지 같게 나온다.**
- 그러나 같은 조건에서 **궤적 중간은 최대 4.7e-2 m 까지 다르다**
  (시드 1000 단일 에피소드 직접 대조).
- → 종단오차는 이 과제에서 **열화에 둔감한 지표**다. 아래 표는
  `IAE = Σ|위치오차|·dt` 와 정착시간을 주 지표로 쓴다.

## 4. 읽는 법 — 깨지는 지점

- **상태지연 ≤ 10 틱(200 ms) · 명령지연 ≤ 5 틱(100 ms) · 손실 ≤ 50 %**
  구간은 `10/10` 이고 IAE 증가가 **9 % 이내**다. 이 범위는 **zero-shot 으로 견딘다.**
- **깨지는 지점은 3개다.**
  | 조건 | 결과 |
  |---|---|
  | 편도 지연 **25 틱 (500 ms)** — 상·하행 어느 쪽이든 | **6/10**, IAE **x1.99**, 끝까지 **미정착** |
  | 왕복 **10+10 틱 (400 ms RTT)** | 9/10, IAE x1.63, 정착 59.7 s (= 에피소드 끝에 겨우) |
  | 손실 **90 %** | 9/10, IAE x1.49, 정착 56.3 s |
- **지연이 손실보다 치명적이다.** 손실 50 % 는 IAE x1.03 인데 편도지연 500 ms 는
  x1.99 다. 손실은 sample-and-hold 로 **직전 값이 남아** 10 Hz 제어주기 안에서
  대개 복구되지만, 지연은 **모든 샘플이 일률적으로 늦어** 위상지연이 된다.
- **상행지연과 하행지연이 거의 같은 영향**을 준다 (`state 5틱` IAE 8.35 =
  `cmd 5틱` IAE 8.35). 루프에서는 두 지연이 더해져 보이기 때문이다
  → 실물 예산은 **RTT 로 잡아야 하고, 400 ms 가 한계선**이다.
- `상태결손` 은 지연 조건에서만 생기고 값이 작다(1~5). 에피소드 **시작 직후**
  정책이 아직 상태를 못 받은 구간이다. 그 동안 행동은 **0 으로 유지**된다
  (`nodes/node_c_nuc.py` 가 `None` 을 돌려주고 `run_harness.episode` 가
  직전 행동을 유지). 실물 거동과 같다.

## 5. 한계

- **zero-shot 이다.** 지연·손실을 넣어 **재학습하면 한계선은 내려간다**(더 좋아진다).
  위 숫자는 "지금 가진 정책을 그대로 올렸을 때"의 보수적 하한이다.
- 에피소드 10개 / 고정 링크시드 1개다. 손실은 확률적이므로 **90 % 행의 9/10 은
  시드 1개의 결과**다 — 실물 예산 산정에는 시드를 늘려야 한다 (확인 필요).
- 지연을 **고정값**으로만 넣었다. 실물 Wi-Fi 는 **지터**가 있고, 지터는 고정지연과
  다르게 작용한다 (확인 필요 — 현재 하네스에 지터 모델이 없다).
